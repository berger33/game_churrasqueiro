# 11 — QA

## 1. Definition of done (§81)

A feature is done only when it is **functional, visual, sonic, instrumented, tested and
documented**. "It works but needs polish" is not done. Every checklist item below is either a
test or a named reviewer sign-off.

## 2. Automated tests

Run with `npm test` (vitest) and, in Unity, `Churrasco.Tests` (EditMode + PlayMode).

| Suite | Covers |
|---|---|
| `data.test.ts` | Schema, referential integrity, cross-file references, launch content minimums, no literal pt-BR strings, no real ad ids, ≥50 achievements, full §59 analytics taxonomy |
| `cooking.test.ts` | Doneness integration, carryover, zone heat, burn threshold, per-ingredient burn rate, flip alternation + cooldown, optimal flip point, cook-duration prediction, stage ladders incl. overrides, all five score qualities, evenness gate, tolerance narrowing, speed bonus, combo cap, slot capacity, charcoal curve + refill, skill policy monotonicity |
| `turn.test.ts` | Customer spawn determinism, patience drain + leave, order matching, combo break rules, turn result and stars |
| `economy.test.ts` | XP curve monotonicity + max-level reachability, upgrade cost monotonicity + multiple of 10, level-up reward curve, offline ramp + cap, ledger faucets/sinks |
| `save.test.ts` | Round-trip, corruption detection, truncation, dual-slot recovery, clock-tamper detection, streak grace day, stable serialisation |
| `monetization.test.ts` | Reward token single-use, duplicate reward rejection, interstitial caps and suppressions, purchase grant-once, restore |
| `golden.test.ts` | Regenerates deterministic vectors for the C# parity test |
| `balance.test.ts` | Runs the simulator and asserts the economy targets |

## 3. What the tests actually caught

Not a formality — these are real defects found and fixed:

1. Perfect rate was 100 % at every skill level (window far too wide).
2. Level-up rewards grew at `1.28^level` → 10.3 M coins at level 47.
3. Customer generosity multiplied the whole plate → 6× swing, 7.7× turn spike.
4. Income plateaued at restaurant 3 (throughput not scaled by tier).
5. Sinks exhausted at level 40 (spend ratio 0.036).
6. `spawnCustomer` used a shared module-level RNG → runs were not reproducible.
7. The balance harness modelled reaction latency with the wrong sign, then omitted charcoal
   efficiency, so it systematically served early.

## 6. Smoke test (every build)

Install → first open → tutorial completes → turn 1 completes → first upgrade → save → kill →
relaunch → progress intact → shop opens → daily reward claims → settings persist.

## 7. Performance gates

| Metric | Gate |
|---|---|
| Crash-free users | > 99 % (target 99.3 %) |
| ANR rate | < 0.3 % |
| Cold start to interactive | < 3.5 s on a mid device |
| Scene load | < 1.5 s |
| GC during a turn | ≤ 1 KB/frame |
| Draw calls | ≤ budget per quality level |
| AAB base size | ≤ 90 MB |
